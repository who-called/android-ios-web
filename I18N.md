## Site (`web/`)

- **Registre** : `web/src/i18n/locales.ts` → `localeRegistry` (URL, dictionnaire, libellé, drapeau, `published`).
- **Textes** : un fichier par langue dans `web/src/i18n/dict/`. `fr.ts` définit la forme (`Dict`),
  `en.ts` est complet, les brouillons (`es`, `it`, `pt`, `ru`) sont des `PartialDict` fusionnés
  par-dessus l'anglais : une clé absente s'affiche en anglais.
  Les tableaux (ex. `guides.items`) sont remplacés en bloc → les traduire entièrement ou pas du tout.
- **Textes légaux** (`legal.ts`) : FR (fait foi) et EN ; les autres langues affichent l'EN.
- **Brouillon vs publié** : une langue `published: false` est accessible (`/es-ES/…`) pour relecture,
  mais absente du sélecteur, du sitemap, des hreflang, jamais choisie via `Accept-Language`, et servie
  avec `X-Robots-Tag: noindex`. Les pages statiques lourdes (numéros, préfixes, guides) ne sont
  pré-générées que pour les langues publiées.
- **Sitemap** : un fichier par langue publiée (`/sitemap/<locale>.xml`, `app/sitemap.ts`) et un index
  `/sitemap.xml` (`app/sitemap.xml/route.ts`) — un seul fichier dépasserait la limite Google de 50 000 URL.
- **Couverture** : `cd web && pnpm i18n:check` (`--missing` pour lister les clés). Échoue si une langue
  publiée est incomplète.

- **Redirection d'une URL sans langue** (`middleware.ts`) : langue du navigateur si elle est publiée,
  sinon (pages `/numero/…` et `/prefixe/…`) langue du pays du numéro (`localeForPhone`),
  sinon anglais (`fallbackUrlLocale`, aussi utilisé pour `hreflang="x-default"`).

**Publier une langue** : traduire `dict/<lang>.ts` jusqu'à 100 % → `published: true` dans `locales.ts`.

**Ajouter une langue** : une entrée dans `localeRegistry`, un fichier `dict/<lang>.ts`, l'ajouter à
`Locale` + `partials` dans `dictionaries.ts`.

## Android (`android/`)

- `values/` = français (déclaré dans `res/resources.properties`), une traduction par dossier `values-<lang>/`.
- `generateLocaleConfig = true` (`app/build.gradle.kts`) : le sélecteur de langue par app d'Android 13+
  est généré depuis ces dossiers.
- Toute l'UI passe par les ressources (`stringResource`, `pluralStringResource`, `@StringRes`) :
  toutes les entrées de `values/strings.xml` sont traduites dans les 13 autres langues. Dates et nombres suivent la langue
  de l'app (`util/UiLocale.kt`, liste `SUPPORTED` à compléter quand on ajoute une langue), repli sur le français.
- Les moteurs de jeu (`game/`) restent sans dépendance Android : l'écran leur passe les textes traduits.
- Contrôle : `./gradlew :app:lintDebug` doit rester à zéro `MissingTranslation` / `StringFormat`.

## iOS (`ios/`)

- `WhoCalled/Localizable.xcstrings` (String Catalog, source `fr`) et `CFBundleLocalizations` dans `Info.plist`.
- ⚠️ Ajouter `Localizable.xcstrings` au target `WhoCalled` dans Xcode, puis builder : Xcode extrait
  automatiquement les `Text("…")` littéraux (~145) dans le catalogue, à traduire ensuite.
  Les textes passés en `String` (interpolations, variables, ~80 cas) doivent passer par
  `String(localized:)` / `LocalizedStringKey` pour être extraits.
